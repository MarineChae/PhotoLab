# LittleCMS original ICC input

2026-10-11, macOS ARM64 / Apple M4 / .NET 10.0.102.

`LittleCmsTransform` owns one LCMS context, source RGB profile, generated linear sRGB D65 profile and float transform. The input is source-encoded straight RGBA32F, output is owned linear sRGB RGBA32F. Relative colorimetric intent, COPY_ALPHA and NOOPTIMIZE preserve alpha and avoid integer quantization; matrix/TRC wide-gamut output retains negative and above-white RGB. Calls are serialized with disposal and performed in 16,384-pixel blocks with cancellation checks. Invalid envelopes, unsupported color spaces and native transform failures throw explicit errors.

`EmbeddedIccProfile` reads original PNG iCCP and JPEG APP2 bytes. PNG decompression and aggregate profile size are limited to 16 MiB; JPEG fragments are ordered and duplicate, missing or inconsistent sequences rejected. This is an ICC extractor, not a replacement for the image codec's full file validation. It reads the header area without copying full image files into memory.

`PHOTOLAB_LCMS_LIBRARY` selects LCMS for JPEG/PNG float loading, including the existing app preview/export source loader. Skia decodes source bytes without performing a color transform; LCMS applies the original ICC once. Untagged RGB assumes sRGB. Non-ICC PNG gamma/chromaticity retains the existing Skia conversion; other image formats also retain Skia. Explicit library/profile failures remain visible. Existing byte APIs and sRGB export encoding retain their previous paths.

Skia `ToProfile()` cannot serialize a constructed RGB space into raw ICC bytes: the initial native test exposed a null buffer. This implementation extracts serialized profiles from actual files instead. Test profiles are generated by Skia PNG/JPEG encoding, with analytic sRGB transfer and independent P3 matrix expectations for native results.

## Dependency and limitations

LittleCMS 2.19.1 is the installed Homebrew runtime. Its [official C API header and MIT license](https://raw.githubusercontent.com/mm2/Little-CMS/master/include/lcms2.h) permit commercial use with copyright/license retention. The [official RGB profile implementation](https://raw.githubusercontent.com/mm2/Little-CMS/master/src/cmsvirt.c) writes copied transfer curves into profile tags. No new NuGet package is introduced; the current application does not bundle LCMS. Distribution needs the platform/architecture-specific dylib or DLL and license notice. Winapi delegates match the Windows DLL ABI and Unix C ABI; Windows binaries remain untested.

Standard image source decode is still RGBA8 and allocates intermediate source bytes, encoded floats and transformed floats before the owned buffer copy. Large-image memory/16-bit input require further work. Original ICC tags now reach LCMS, but LUT-profile reference coverage is pending. Monitor profile discovery/conversion, soft proofing, non-sRGB export and packaged native runtime are also pending. The project goal remains active.
